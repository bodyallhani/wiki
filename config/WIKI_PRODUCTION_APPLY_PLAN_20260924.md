# 운영 품질 검수 연결 계획

대상은 비활성 상태의 KO 작성 시나리오 **7319449**입니다. 새 연결은 현재 격리 시나리오 **7581728**에서 시험 중입니다. 자동 승인 검토가 운영 구성 변경을 승인 범위 밖으로 판단하여 실제 연결은 적용되지 않았습니다.

## 적용할 변경

1. 검증 논문 집계 22 다음에 공개 한국어 본문 수집을 추가합니다. main의 커밋과 트리를 고정한 뒤 sitemap에 없는 과거 번호 기사도 포함합니다. 같은 배치의 VERIFIED 논문 2건 조건을 그대로 유지합니다.
2. 작성 모듈 2에 최신 Claude 작성 지침과 관련 기존 글의 질문 개요를 연결합니다. 기존 본문은 중복 비교 자료로만 사용합니다.
3. 작성 뒤 구조 검사 → 전체 관련 본문 비교 → 독립 Claude 검수 → 코드 판정을 연결합니다. 연구·병원 진료·응급 안내·읽기 품질의 4개 세부 판정과 8개 필수 기준을 모두 요구합니다.
4. 실패하면 같은 Claude가 정확한 지적을 반영해 1회 수정하고 동일 검수를 다시 받습니다. 통과 및 수정 경로를 합쳐 하나의 문서와 검수기록을 반환합니다.
5. 최종 게이트 1205는 원고·문서·비교 corpus 해시를 확인합니다. 실패 시 기존 보류·오류 처리 경로를 사용하고 이미지와 schema 단계로 진행하지 않습니다.
6. 기존 협소한 방어문 보정 호출 1210/1211/1212는 새 수정 경로가 완성된 뒤 제거합니다. 이미지·번역·의료진 승인·공개 발행의 기존 제어는 유지합니다.

## 적용 방법과 검증

- Make가 부여한 새 모듈 ID를 매번 받아 실제 참조로 연결합니다. 격리 시험의 1460 등 ID를 운영에 임의로 가정하지 않습니다.
- 입력이 비어 있는 모듈을 임시 삽입하지 않습니다. 읽기·쓰기 충돌 방지를 위해 expectedLastEdit를 사용하고 매 응답의 applied/errors를 확인합니다.
- 적용 전 설정을 보존하고, 적용 후 흐름·참조·필터·구성 오류와 비활성 상태를 다시 확인합니다.
- 운영 활성화나 실행은 이 설정 변경에 포함하지 않습니다. 비공개 격리 흐름에서 검증한 뒤 운영 제어가 허용하는 정상 실행으로 넘어갑니다.

## 승인 요청이 필요한 정확한 범위

**7319449를 비활성 상태로 유지하면서 위 공개 본문 비교·독립 검수·1회 자동 수정·최종 해시 게이트를 운영 구성에 연결하고 구 보정 호출을 교체하는 변경.**

전체 스케줄 활성화, 0028 공개, Slack 전송은 이 범위에 포함하지 않습니다. 0027의 기존 승인 및 9월 25일 19:10 KST 1회 공개 예약은 유지합니다.
