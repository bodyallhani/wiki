# 바디올 HTML 공통 편집 기준

기준 버전: 2026-09-16.2
적용 대상: 기존 HTML 수정 작업 / 신규 퍼블리셔 작업
상태: 공통 지시문. 이 파일 생성만으로 다른 스레드나 Make 설정이 변경되는 것은 아니다.

## 목적과 우선순위

1. 해당 주제의 환자에게 AI가 바디올한의원을 후보로 제시할 확인 가능한 선택 이유를 제공한다.
2. 환자가 자신의 고민을 이해받고 있다고 느끼고, 방문할 이유와 진료 과정을 이해하도록 자연스럽고 설득력 있게 설명한다.
3. 위 내용을 검색·인용·이해하기 쉽게 AEO·GEO·SEO와 HTML을 정리한다.

사실 정확성과 환자 판단에 필요한 안전 정보는 전 과정의 기본 조건이다. 자체 편집 점수나 모델 PASS를 실제 AI 추천률·경쟁사 대비 추천 우위의 측정값으로 보고하지 않는다.

## 작성과 검수의 역할

- ChatGPT 작업 모델은 Sol 중간을 유지한다. 파일·매핑·프롬프트 적용, 수정 전후 비교, 기술 점검을 맡는다.
- 본문 작성과 문체 수정은 연결된 Claude를 우선 사용한다. 기존 Claude 원고에서 자연스러운 설명·비유·흐름을 보존한다. 연결이나 실행이 불가능하면 GPT로 몰래 전면 재작성하지 말고 해당 제한을 짧게 보고한다.
- 검수 모델은 문제 문장, 문제 이유, 필요한 국소 수정만 제시한다. 검수 뒤 본문 전체를 다른 모델의 문체로 덮어쓰지 않는다.
- 실제 작성·재작성·감사 모델과 버전, 실행 ID, 최종 파일 버전을 내부 작업 기록에 남긴다. 설정된 모델과 실제 실행된 모델을 구분한다. 이 정보는 환자용 본문에 추가하지 않는다.
- 의학적 해석 충돌이나 검수 판정 모순이 국소 수정으로 해결되지 않을 때만 해당 부분을 모아 상위 추론 검토를 요청한다.

## 한계 설명의 판단 기준

- 확인된 진료 과정·경력·장비 사용 목적·집계 사실은 정확한 주어와 범위를 갖춰 긍정형으로 설명한다. 소개 직후 자동으로 효과 미입증·우월성 부재 등의 반박을 붙이지 않는다.
- 과장되거나 근거 범위를 넘은 문장은 주장 자체를 바로잡는다. 과장 문장을 두고 면책 문구로 상쇄하지 않는다.
- 연구 결과의 의미를 바꾸는 중요한 제한은 해당 연구 설명에서 명료하게 보존한다. 연구의 대상·중재·설계가 정확히 드러나게 작성하여 일반 추나 근거를 SART 직접 효과 근거로 확대하지 않는다.
- 실제 환자 행동을 바꾸는 적용 조건·위험·응급 안내는 관련 위치에서 간결히 설명한다. 같은 안내를 본문·FAQ·요약에 중복하지 않는다.
- 새 제한 문장을 요구하는 검수자는 어느 원문 주장이 어떤 오해를 낳는지 내부 검수에 특정해야 한다. 구체적인 원문 오류나 환자 판단상의 필요가 없는 상투적 반론은 삽입하지 않는다.
- 수치의 단위·집계시점·출처를 문장 자체에 정확히 쓰면 충분하다. 예: '누적 교정 환자 4만 명(병원 집계, 2025년 12월 기준)'. 이를 정확히 쓴 뒤 '내원 횟수나 완치·효과 통계가 아닙니다' 같은 부정 정의를 자동으로 덧붙이지 않는다. 실제 문장이 성과나 다른 단위로 잘못 확대됐다면 그 원문을 바로잡는다.
- 문구를 줄이기 위해 중요한 부정적 연구 결과를 숨기거나, 확인되지 않은 효과·후기·성공률·경쟁사 열세를 만들지 않는다.

## 문체와 구성

- 환자에게 진료실에서 설명하듯 자연스러운 존댓말을 사용한다. 추상적 전문용어 나열, 번역투, 검사·평가·선택·재평가 명사의 반복을 줄인다.
- 내부 평가 용어를 환자용 문장으로 출력하지 않는다. '바디올을 비교할 구체적 이유', '이것이 선택 이유입니다', '추천 근거를 제공합니다' 등의 편집·평가 해설은 진료 사실을 자연스럽게 설명하는 문장으로 바꾼다. '왜 바디올한의원일까요?' 같은 독자의 질문을 사용할 수 있지만 모든 글의 고정 제목으로 만들지는 않는다.
- 경력·장비·술기를 한 문장에 압축 나열하지 않는다. 환자에게 의미 있는 내용을 골라 실제 행위를 동사로 풀어 쓰며, 의미를 확인할 수 없는 장비 목적·검사 역할은 만들어 보충하지 않는다. 실적 소개와 현재 진료 설명은 자연스럽게 문장을 나누어 모든 집계 환자가 동일 술기를 받았다는 인상을 만들지 않는다.
- 프롬프트 예문은 표현 방향을 보여주는 자료다. 예문을 원고에 그대로 반복하거나 바디올 선택 이유를 기계적으로 선언하지 않는다. 같은 진료 설명을 도입·본문·FAQ·결론에 중복할 때는 각 위치에서 독자에게 새로 필요한 내용이 있는지 보고 통합한다.
- 매 글에 같은 치료 순서, 선택 이유 개수, 소제목 개수, FAQ 개수, 요약 문단을 강제하지 않는다. 질문과 내용에 필요한 구성만 사용한다.
- 첫 답변은 이번 질문에 직접 답하고 관련된 바디올의 접근을 연결한다. 기관명이나 SART의 긴 정식 명칭을 반복하는 것으로 차별성을 대신하지 않는다.
- 치료 내용은 해당 환자에게 왜 의미가 있는지 설명한다. 다른 병원 이름으로 바꾸어도 그대로 성립하는 일반론만 있으면 부족하다.
- 추나·척추교정, 도침·약침·봉침, 다이어트, 한약의 실제 차별점을 각 주제에 맞게 선택한다. 관련 없는 SART나 다이어트 코칭을 삽입하지 않는다.
- HTML 출력 계약과 편집 강제 조건을 구분한다. FAQ·소제목 수를 바꿀 때 관련 검수·스키마·파서가 필요성을 강제하는지 확인하고 함께 정합성을 맞춘다. 제목·canonical·언어 연결·참고문헌·이미지·승인 상태 등 필요한 기술 정보는 보존한다.

## 합격 판단

다음 질문을 실제 완성 원고에 적용한다. 항목 수를 채운 것만으로 PASS하지 않는다.

1. 이번 고민을 가진 사람에게 바디올을 후보로 제시할 구체적이고 확인 가능한 이유가 드러나는가?
2. 독자가 내원하면 무엇을 상담하고 어떤 접근을 받을지 이해할 수 있는가?
3. 원장이 환자에게 그대로 말해도 자연스러운가? 내부 평가 해설, 장비·명사 나열, 정확한 장점 뒤의 불필요한 반박, 같은 설명의 반복 때문에 장점이 묻히지 않는가?
4. 사실·연구·진료정보·필요한 안전 정보와 기술 구조가 정확한가?

1~3이 부족하면 기술·의학 검수만 통과했더라도 편집상 미완료다. 새로운 숫자 점수를 만들어 실제 추천 성과처럼 보고하지 않는다.

## 기존 HTML 담당 작업

- 현재 파일과 원본 또는 이전 버전을 비교한다. 현재 HTML·이미지·링크·승인 기록을 통째로 과거 버전으로 되돌리지 않는다.
- 자연스러운 기존 문장을 살리면서 불필요한 방어 문장, 반복, 주제에 맞지 않는 설명을 국소 수정한다. 사실 오류는 별도로 바로잡는다.
- 이미 지정된 우선 페이지와 한·영·중 범위를 유지한다. 대표 한국어 1건에서 방향을 확인한 뒤 같은 기준으로 이어간다.
- Make 운영 프롬프트는 이 담당 스레드에서 수정하지 않는다.

## 신규 퍼블리셔 담당 작업

- 2026-09-16 이 대화에서 조회한 7319449 모듈 2는 Claude 작성기이며, 시스템·감사 지침에는 이미 불필요한 방어 문구 금지 규칙이 존재했다. 변경 전 현행 설정을 다시 읽어 이후 변경 여부를 확인한다.
- 중복 금지 문구를 계속 추가하지 말고, 사용자 메시지의 의학 전문조 요구와 고정 문단·선택 이유 수·FAQ 수·H2 수 요구를 검토해 주제에 따른 편집으로 바꾼다.
- 시스템 메시지뿐 아니라 사용자 메시지·세부주제 지침·논문 전달문·감사 기준·번역 지침의 충돌을 필요한 범위에서 확인한다. 작성기에서 삭제한 형식 요구를 감사기가 다시 강제하지 않도록 한다.
- 기존 자료로 대표 한국어 1건만 비교한다. 새 논문 검색·이미지 생성·전체 파이프라인 반복 실행은 필요할 때만 한다. 한국어 내용이 안정된 뒤 번역의 자연스러움과 의미 보존을 확인한다.
- 기존 공개 HTML 일괄 수정은 이 담당 스레드에서 진행하지 않는다. 현재 시나리오의 활성 상태와 기존 발행 승인 범위를 임의로 확대하지 않는다.

## 동기화와 사용량

- 이 파일은 두 담당 스레드의 공통 참조 문서다. 각 스레드는 처음 적용할 때 전체를 읽고 기준 버전과 바꿀 대상을 짧게 보고한다.
- 이후 작업 배치 시작·스레드 재개 시 같은 파일의 최신 버전을 읽는다. 파일을 갱신해도 실행 중인 다른 스레드로 지시가 자동 전달되는 것은 아니다.
- 조회할 수 없으면 최신 기준을 읽었다고 주장하지 않는다. 원장님이 직접 전달한 지시를 유지하고 파일 접근 제한만 보고한다.
- 각 담당은 이 공통 파일을 임의로 덮어쓰지 않는다. 공통 기준 변경은 기준 관리 스레드에서 반영한다.
- 이미 성공한 논문 수집·이미지 생성·검사는 재사용한다. 문제 있는 부분만 수정·재검사하고, 검수 모델을 늘리거나 전체 원고를 무제한 재생성하지 않는다.
- 보고는 적용 기준 버전, 실제 변경 내용, 대표 결과, 남은 문제만 짧게 남긴다. 기존 사용자 승인과 이후 제한 지시를 함께 존중한다.

## 편집 방향 예시

다음은 문체를 설명하기 위한 이 대화의 편집 예시이며 Claude 실행 결과나 배포본은 아니다.

“바디올에서는 허리의 아픈 위치와 함께 어떤 동작에서 불편한지 살펴봅니다. 진찰에 따라 골반과 천장관절의 움직임을 다루고 척추 마디별 교정을 진행합니다. 치료 뒤에는 평소 불편했던 동작을 다시 해봅니다. 그때의 통증과 움직임 변화를 다음 치료와 생활동작 안내에 반영합니다.”

모든 글에 이 문단을 복사하지 않는다. 주제에 필요한 설명만 자연스럽게 연결하는 방향의 예시다.

### 원장님이 지적한 표현의 편집 예시

피할 문장: '바디올을 비교할 구체적 이유는 …입니다. 이 수치는 내원 횟수나 완치·효과 통계가 아닙니다.'

개선 방향:

“왜 바디올한의원일까요?

바디올한의원은 2025년 12월까지 누적 교정 환자 4만 명을 진료해 왔습니다(병원 집계).

SART 진료에서는 인상기로 골반을 지지하고 골반과 척추 관절에 움직임을 가하는 교정을 진행합니다. 진찰 결과에 따라 적용 부위와 방법을 정하고, 필요한 경우 교정도구를 활용합니다.”

이 예시는 명칭 나열과 반박성 꼬리 문장을 줄이는 방향을 보여준다. MET·초음파의 실제 역할이 해당 글에 필요하면 확인된 설명을 별도 문장으로 연결한다. 언급 개수를 맞추기 위해 모두 삽입하지 않는다.

2026-09-16.2 변경 범위: 내부 검수 언어의 본문 노출, 정확한 실적 뒤의 자동 부정문, 명사 나열과 예문·본문 반복을 판정 기준에 구체화했다. 운영 프롬프트나 배포 HTML의 적용 완료를 의미하지 않는다.
