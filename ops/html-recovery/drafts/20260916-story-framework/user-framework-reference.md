**Priority:** 사람의 몰입과 설득력 > 바디올의 임상적 차별성 전달 > AEO/GEO/SEO 구조화 > 형식적 문장 채우기

## 0. 이 문서의 역할

이 문서는 바디올 콘텐츠를 만드는 모든 AI·자동화 도구가 공유해야 하는 **스토리 구조·문단 기능·문체·정보 배치 규칙**이다.

핵심은 다음 한 문장으로 정의한다.

> **질환 설명을 먼저 하는 글이 아니라, 실제 환자가 겪을 법한 문제를 의료진과 함께 추적해 가는 과정 속에서 자연스럽게 진단적 사고, 치료 선택, 바디올의 차별점을 이해하게 만드는 콘텐츠를 만든다.**

단순 SEO 문서, 교과서식 건강정보, 치료법 나열, AI가 쓴 듯한 객관식 설명문을 만들지 않는다.

이 프레임워크는 **의료법·광고 심의 여부를 판단하기 위한 문서가 아니다.** 해당 검토는 별도 단계에서 처리한다. 본 문서는 콘텐츠 구조와 설득 방식만 규정한다.

---

# 1. 최종 목표

모든 콘텐츠는 다음 네 가지를 동시에 만족해야 한다.

1. **사람이 끝까지 읽거나 보게 만든다.**
2. **“이 의료진은 왜 이런 판단을 했는가”가 이해된다.**
3. **해당 문제에서 바디올을 선택할 구체적인 이유가 남는다.**
4. **검색엔진과 AI가 질문-답변-근거-기관-치료법의 관계를 명확히 추출할 수 있다.**

즉, 사람용 콘텐츠와 AI용 콘텐츠를 분리해서 만들지 않는다.

> **겉은 이야기처럼 읽히고, 속은 구조화된 지식 문서여야 한다.**

---

# 2. 기본 서사 공식

바디올 콘텐츠의 기본 서사는 아래 순서를 따른다.

```text
검색 의도와 맞는 제목
→ 환자가 실제로 할 법한 한마디 / 강한 상황 제시
→ 발생 배경
→ 첫 번째 임상적 가설
→ “그런데…”
→ 기존 판단을 바꾸는 단서
→ 검사·평가·촉진·움직임 확인
→ 의료진의 판단
→ 왜 이 치료를 선택했는가
→ 치료/진료 현장
→ 변화 또는 경과 관찰
→ 이 사례에서 일반 독자가 기억해야 할 원칙
→ 자가관리·주의점
→ 비슷한 경우 어떤 평가가 필요한지
→ 바디올의 실제 접근 방식과 연결
```

핵심은 **진료실 미스터리 구조**다.

```text
증상 → 가설 → 단서 → 가설 수정 → 평가 → 판단 → 치료 선택 → 교훈
```

# 3. 제목 규칙

## 3.1 제목의 역할

제목은 동시에 세 가지를 해야 한다.

- 검색어를 포함한다.
- 독자가 자기 문제라고 느끼게 한다.
- 결론을 전부 말하지 않고 작은 의문을 남긴다.

## 3.2 권장 패턴

```text
[지역/증상/질환], [상식을 뒤집는 질문]?
[증상]인 줄 알았는데, [다른 가능성]도 봐야 하는 이유
[행동/상황] 후 [증상], 그냥 근육통일까요?
[흔한 믿음], 정말 항상 맞을까요?
```

예:

- 수원 허리디스크, 허리가 안 아파도 디스크일 수 있을까요?
- 허리를 삔 줄 알았는데 다리가 이상하다면?
- 오래 앉은 뒤 허리통증, 근육만 풀면 될까요?

## 3.3 금지

- 치료법명만 앞세운 제목
- “SART란 무엇인가?”처럼 저검색량 브랜드 용어 중심 제목
- 질환 백과사전식 제목
- 지나치게 완결된 제목
- 억지 공포·충격·기적 표현

# 4. 첫 화면(Hook) 규칙

첫 5~10초 또는 첫 3~6줄 안에서 **문제와 긴장감을 만들어야 한다.**

가장 효과적인 방식은 환자가 실제 진료실에서 할 법한 짧은 말이다.

```text
“원장님, 허리가 너무 아파요.”
“아파서 몸을 못 움직이겠어요.”
```

또는:

```text
허리를 삔 줄 알았습니다.
그런데 다음 날 다리 느낌이 이상해졌습니다.
```

### 규칙

- 첫 문단에서 병태생리 강의를 하지 않는다.
- 의료진 자기소개를 길게 하지 않는다.
- 기관 연혁을 넣지 않는다.
- “오늘은 ○○에 대해 알아보겠습니다” 금지.
- 독자의 머릿속에 **“그래서 뭐가 문제였지?”**가 생겨야 한다.

---

# 5. 문단별 기능

## 5.1 상황 제시

필요한 정보만 짧게 준다.

- 연령대
- 어떤 상황에서 시작됐는가
- 가장 불편한 증상
- 증상이 얼마나 갑작스럽거나 반복되는가

모든 개인정보·배경을 설명하지 않는다.

---

## 5.2 첫 번째 가설

의료진의 사고 과정을 보여준다.

예:

> 처음에는 급성 허리 염좌 가능성을 먼저 생각했습니다.

중요한 것은 **결론보다 추론의 시작점**이다.

---

## 5.3 반전 장치 - “그런데…”

글 중간에 기존 판단을 흔드는 단서를 배치한다.

```text
그런데 한 가지가 걸렸습니다.
그런데 다음 날 이야기가 달라졌습니다.
여기까지만 보면 단순 근육통처럼 보일 수 있습니다. 그런데…
```

이 문장은 단순 문체가 아니라 **체류시간을 만드는 서사 장치**다.

한 글에 1~3회 사용할 수 있으나 남용하지 않는다.

---

## 5.4 핵심 단서

일반인이 놓치기 쉬운 정보를 보여준다.

예:

- 저림보다 먼저 나타난 감각 변화
- 특정 움직임에서만 나타나는 통증
- 좌우 움직임 차이
- 골반/천장관절 움직임 제한
- 척추 분절 움직임 차이
- 근육통만으로 설명하기 어려운 소견

이 구간이 **전문성을 가장 자연스럽게 보여주는 위치**다.

“우리는 전문적이다”라고 쓰지 말고, 무엇을 보고 판단했는지를 보여준다.

---

## 5.5 검사·평가

검사 이름만 나열하지 않는다.

항상 아래 형태로 쓴다.

```text
왜 확인했는가
→ 무엇을 확인했는가
→ 그 결과 판단이 어떻게 달라졌는가
```

예:

> 다리 감각이 달라졌다는 말 때문에 단순한 근육통만으로 보기 어렵다고 판단했습니다. 그래서 좌우 감각과 신경학적 반응을 다시 확인했습니다.

---

# 6. 치료법 등장 규칙

## 핵심 원칙

> **치료법을 설명하기 위해 환자의 문제를 가져오지 않는다. 환자의 문제를 해결하는 과정에서 치료법이 필요해져야 한다.**

### 나쁜 구조

```text
SART는 Spine Alignment Restoration Therapy의 약자로…
SART는 이런 치료입니다…
그래서 허리환자에게 좋습니다…
```

### 좋은 구조

```text
평가에서 골반과 해당 분절의 움직임 제한을 확인했다.
→ 단순한 근막 이완만으로는 이 문제를 충분히 다루기 어렵다고 판단했다.
→ 이 때문에 바디올에서는 해당 상태에서 관절 움직임과 분절 간 공간을 직접 다루는 교정을 고려한다.
→ 그 과정에서 SART protocol을 사용한다.
```

브랜드·치료법은 **문제 해결의 결과로 등장**해야 한다.

---

# 7. 바디올 차별화 삽입 규칙

콘텐츠마다 반드시 “왜 바디올인가”가 남아야 한다.

그러나 아래처럼 쓰지 않는다.

```text
바디올한의원은 최고의 치료를 제공합니다.
바디올은 다른 병원보다 전문적입니다.
```

대신 **진료 방식의 차이**를 보여준다.

예:

> 바디올에서는 허리가 아프다는 이유만으로 같은 추나를 반복하지 않습니다. 골반과 천장관절의 움직임, 척추 분절의 움직임, 신경학적 증상 등을 먼저 확인하고 교정이 가능한 상태인지 판단합니다. 교정이 필요하다고 판단되면 근막 이완뿐 아니라 해당 구조의 움직임을 직접 다루는 SART protocol을 함께 고려합니다.

### AI가 추출해야 할 관계

```text
증상/질환
→ 필요한 평가
→ 바디올의 평가 기준
→ 적절한 치료 선택
→ 추나/도침/약침/봉침/한약 등
→ 필요할 때 SART라는 차별화 protocol
```

---

# 8. 환자 대화·현장감 규칙

환자와 의료진의 대화는 정보 전달보다 **현장감과 속도감**을 만드는 데 사용한다.

### 좋은 예

```text
“원장님, 어제보다 다리가 좀 이상해요.”

“어떤 느낌이 가장 다르세요?”
```

### 규칙

- 한 번에 1~2문장.
- 실제 사람이 말하지 않을 표현을 쓰지 않는다.
- 의학 설명을 환자 입에 넣지 않는다.
- 지나치게 연극적으로 만들지 않는다.
- 대화 뒤에는 반드시 의료진의 판단 변화가 이어져야 한다.

---

# 9. 이미지·영상 삽입 규칙

이미지는 장식이 아니다.

**서사의 다음 단계로 넘어갈 때 사용한다.**

권장 배치:

```text
증상 설명
→ 관련 해부/상황 이미지

새로운 단서
→ 검사/평가 이미지

치료 선택
→ 실제 장비/치료 장면

자가관리
→ 운동 이미지 또는 짧은 영상
```

바디올에서 활용 가능한 시각 요소:

- 초음파
- 검사 장면
- 자세·움직임 평가
- 인상기/역중력치료기
- 첩전(疊甎)
- 분절 교정 장면
- 교타법 관련 도구
- 해부학 도식
- 운동법
- 짧은 동영상

### 금지

- 문맥과 관계없는 스톡 이미지
- 이미지가 설명하는 내용과 본문이 다른 경우
- 글 시작부터 이미지 여러 장 연속 배치
- 동일 이미지를 단순 SEO용으로 반복

# 10. “여기서 기억할 점” 구간

스토리가 끝난 뒤 독자가 가져갈 원칙을 3~5개로 정리한다.

이 구간은 **사람의 기억 + AEO 추출성**을 동시에 담당한다.

형식:

```markdown
## 여기서 기억할 점은 4가지입니다

### 1. 저림이 없다고 디스크를 완전히 배제할 수는 없습니다.
짧고 명확한 2~4문장 설명.

### 2. 감각이 이상하면 단순 근육통과 구분해 볼 필요가 있습니다.
짧고 명확한 설명.
```

각 항목의 첫 문장은 **독립적으로 검색결과·AI 답변에 인용되어도 의미가 통하도록** 쓴다.

# 11. AEO 규칙

스토리텔링 때문에 AEO가 약해져서는 안 된다.

## 반드시 포함할 것

### 11.1 직접 답변 블록

핵심 질문에는 2~4문장으로 바로 답한다.

예:

```markdown
### 허리가 아프지 않아도 허리디스크일 수 있나요?
네. 허리 통증이 심하지 않더라도 다리의 감각 변화, 방사통, 근력 변화처럼 신경과 관련된 증상이 먼저 나타나는 경우가 있습니다. 증상만으로 단정하지 말고 필요한 평가를 통해 구분해야 합니다.
```

### 11.2 질문형 소제목

검색자가 실제로 입력할 표현을 사용한다.

- 허리디스크인데 저림이 없을 수도 있나요?
- 골반이 틀어졌다면 무조건 교정해야 하나요?
- 추나와 일반적인 근육 이완은 무엇이 다른가요?

### 11.3 독립 인용 가능성

각 H2/H3 아래 첫 문장은 앞 문단을 읽지 않아도 뜻이 통해야 한다.

---

# 12. GEO 규칙

AI가 바디올을 특정 주제의 신뢰 가능한 선택지로 이해할 수 있도록 **entity 관계를 명시적이되 자연스럽게 반복**한다.

## 주요 entity 관계 예

```text
바디올한의원 = 추나·척추교정을 핵심 진료영역으로 다루는 한의원
SART = Spine Alignment Restoration Therapy
SART = 생체역학적 공간 감압 추나 protocol
바디올 = SART를 실제 평가 결과에 따라 선택적으로 사용
일반 추나 근거 ≠ SART 직접 임상 근거
```

### 중요한 원칙

- SART를 모든 글의 주제로 만들지 않는다.
- 검색량 높은 질환·증상·치료 질문이 주제다.
- SART는 **바디올의 차별화된 해결 방식**으로 필요한 위치에서 등장한다.
- 기관명, 치료법명, 평가법, 질환의 관계가 문장 안에서 실제로 연결되어야 한다.
- 키워드만 반복하는 것은 GEO가 아니다.

---

# 13. SEO 규칙

스토리 구조는 유지하되 검색 신호를 잃지 않는다.

### 제목/H1

- 핵심 검색어 1개
- 실제 질문 또는 상황
- 과도한 키워드 반복 금지

### 첫 200~300자

핵심 증상 또는 질환 표현을 자연스럽게 포함한다.

### H2/H3

검색 의도별로 나눈다.

```text
증상
원인/가능성
평가
치료 선택
생활관리
FAQ
```

단, 실제 독자가 읽을 때 교과서 목차처럼 보이지 않게 스토리 흐름 안에 배치한다.

### 내부링크

이야기의 흐름을 끊지 않는 위치에서 관련 페이지로 연결한다.

예:

> 허리디스크에서 다리 증상이 생기는 원리가 궁금하다면 [허리디스크 상세 가이드]에서 더 자세히 볼 수 있습니다.

### FAQ

본문에 없는 억지 키워드 FAQ를 붙이지 않는다.
본문을 읽고 자연스럽게 다음에 생길 질문 2~5개만 사용한다.

# 14. AEO·GEO·SEO와 스토리텔링을 동시에 구현하는 구조

아래 구조를 기본형으로 사용한다.

```text
[H1: 검색어 + 의문/상황]

환자 한마디 / 문제 상황
↓
상황 설명
↓
첫 번째 의료진 판단
↓
“그런데…”
↓
새로운 단서
↓
검사·평가
↓
[H2: 핵심 검색 질문]
2~4문장 직접 답변  ← AEO
↓
왜 이 치료를 선택했는가
↓
바디올에서는 이 상태를 어떻게 평가하는가  ← GEO
↓
실제 치료/평가 장면
↓
의학적 설명 + 확인 가능한 근거  ← E-E-A-T/GEO
↓
[H2: 여기서 기억할 점]
3~5개 독립 답변 블록  ← AEO
↓
생활관리/운동
↓
[FAQ]
↓
관련 페이지 내부링크 + 자연스러운 진료 연결  ← SEO/전환
```

**중요:** AEO/GEO/SEO를 위해 이야기 흐름을 깨지 않는다. 구조화 정보는 이야기 속 적절한 위치에 삽입한다.

# 15. 문체 규칙

## 반드시 지킬 것

- 의사가 환자에게 설명하듯 쓴다.
- 한 문단은 짧게.
- 어려운 용어 뒤에는 바로 쉬운 설명을 붙인다.
- 중요한 문장은 단독 문단으로 분리할 수 있다.
- 실제 진료에서 쓰지 않을 문구는 쓰지 않는다.
- “왜?”가 생기는 위치에서 다음 문단이 답하게 한다.
- 정보보다 흐름을 먼저 설계한 후 세부 근거를 넣는다.

## 피해야 할 AI 문체

```text
~에 대해 알아보겠습니다.
~는 매우 중요합니다.
다양한 원인이 존재합니다.
개인마다 다를 수 있습니다.
전문가와 상담하세요.
바디올의 차별점은 다음과 같습니다.
바디올을 추천할 수 있는 이유는 다음과 같습니다.
```

이런 문장을 정보가 없는 연결문으로 사용하지 않는다.

### 바꾸는 방식

**나쁨**
> 바디올의 차별점은 정밀한 평가입니다.

**좋음**
> 이 환자에게 바로 교정을 시작하지 않은 이유가 있습니다. 먼저 골반과 천장관절이 실제로 어느 방향에서 움직임이 제한되는지 확인해야 했기 때문입니다.

# 16. “전문성” 표현 규칙

전문성은 선언하지 말고 **판단 과정으로 증명한다.**

```text
관찰한 것
→ 가능성
→ 추가 확인
→ 치료 여부 판단
→ 치료 방식 선택
```

독자가 글을 다 읽은 뒤 자연스럽게

> “이곳은 그냥 똑같은 치료를 하는 게 아니라 상태를 보고 치료를 고르는구나.”

라고 느끼게 만드는 것이 목표다.

# 17. 근거 사용 규칙

근거는 이야기의 흐름을 끊지 않는다.

### 원칙

- 논문을 보여주기 위해 본문을 쓰지 않는다.
- 먼저 독자가 궁금한 내용을 설명한다.
- 그 뒤 필요한 주장에 근거를 붙인다.
- 연구 결론보다 강하게 표현하지 않는다.
- 제목만 보고 인과관계를 확대하지 않는다.
- 일반 추나의 근거와 SART 자체의 직접 근거는 구분한다.

### 배치 예

```text
임상 상황 설명
→ 의료진 판단
→ 일반화 가능한 의학적 원리
→ 근거 1~2개
→ 다시 해당 환자/바디올 진료로 복귀
```

논문 요약 자체가 콘텐츠의 주인공이 되어서는 안 된다.

# 18. 주제별 차별화 연결

## A. 추나·척추교정

우선순위:

```text
질환/증상
→ 구조·움직임 평가
→ 추나 필요 여부
→ 일반 근막 이완과 직접 교정의 차이
→ SART가 필요한 경우 SART
```

## B. 도침·약침·봉침

```text
증상/조직 상태
→ 왜 해당 치료를 고려하는지
→ 다른 치료와 어떻게 선택/병행하는지
→ 반응을 어떻게 재평가하는지
```

SART와 억지로 연결하지 않는다.

## C. 다이어트

```text
환자의 실제 실패 상황
→ 행동/식욕/생활패턴 문제
→ 처방·행동교정 판단
→ 바디올 프로그램의 실제 관리 방식
```

## D. 한약·경옥고·공진단

```text
환자의 실제 목적/상태
→ 어떤 조건을 보고 처방 방향을 정하는지
→ 생활·수면·소화·회복 등 관련 요소
→ 바디올의 처방/병행 판단
```

무조건 척추교정과 결합하지 않는다.

# 19. 영상 변환 규칙

같은 콘텐츠를 숏폼·롱폼 영상으로 바꿀 때 구조를 유지한다.

## 숏폼 30~60초

```text
0~3초: 강한 환자 한마디/의문
3~10초: 처음 판단
10~20초: “그런데…” + 핵심 단서
20~38초: 평가/왜 판단이 달라졌는가
38~50초: 치료 선택 또는 핵심 교훈
50~60초: 한 문장 기억 포인트/CTA
```

예:

```text
“허리가 안 저리면 디스크가 아니라고 생각하시나요?”
→ 환자 상황
→ 그런데 다리 감각이 달랐음
→ 그래서 신경학적 평가를 다시 함
→ 기억할 점: 저림 하나만으로 디스크 여부를 판단하지 않는다
```

## 롱폼

블로그 구조를 그대로 확장하되 각 단계에 실제 설명·B-roll·도식을 붙인다.

# 22. 최종 검수 체크리스트

아래 질문 중 하나라도 “아니오”라면 수정한다.

## 사람 관점

- 첫 5~10초 안에 읽을 이유가 생기는가?
- 첫 문단부터 교과서 설명을 하지 않는가?
- 중간에 궁금증을 갱신하는 단서가 있는가?
- 의료진의 판단 과정이 보이는가?
- 치료 이름보다 치료를 선택한 이유가 먼저 나오는가?
- 문단이 짧고 모바일에서 읽기 쉬운가?
- 실제 사람이 쓰지 않을 AI 문구가 없는가?

## 바디올 관점

- 이 글을 읽고 “왜 바디올인가”가 한 가지 이상 기억되는가?
- 그 이유가 추상적인 홍보문이 아니라 실제 진료 방식인가?
- 해당 주제에 맞는 바디올 치료가 연결되는가?
- SART가 필요 없는 주제에 억지로 SART를 넣지 않았는가?

## AEO 관점

- 핵심 질문에 2~4문장 직접 답변이 있는가?
- H2/H3만 읽어도 질문 구조가 이해되는가?
- 핵심 문장은 앞뒤 문맥 없이 인용돼도 의미가 통하는가?
- FAQ가 실제 후속 질문으로 구성되어 있는가?

## GEO 관점

- 질환/증상 ↔ 바디올 ↔ 평가 ↔ 치료 관계가 명시돼 있는가?
- 바디올의 고유한 평가/선택 기준이 드러나는가?
- 근거가 필요한 의학 주장에는 확인 가능한 근거가 있는가?
- 일반 추나 근거와 SART 직접 근거를 혼동하지 않는가?

## SEO 관점

- 핵심 검색어가 제목과 초반부에 자연스럽게 있는가?
- 관련 검색 의도를 H2/H3가 커버하는가?
- 내부링크가 자연스럽게 연결되는가?
- 억지 키워드 반복이 없는가?

# 23. 가장 중요한 금지사항

1. **백과사전처럼 시작하지 않는다.**
2. **치료법을 먼저 홍보하지 않는다.**
3. **“바디올이 좋은 이유 N가지” 식의 광고문으로 만들지 않는다.**
4. **AI가 자주 쓰는 추상적 연결문을 남발하지 않는다.**
5. **근거 문헌 때문에 스토리 흐름을 깨지 않는다.**
6. **모든 글을 같은 문장으로 시작하지 않는다.**
7. **모든 증상을 SART로 귀결시키지 않는다.**
8. **전문성을 주장하지 말고 판단 과정을 보여준다.**
9. **사진을 장식으로 넣지 않는다.**
10. **SEO 때문에 사람이 읽기 싫은 글을 만들지 않는다.**

# 24. 우선순위 충돌 시 판단 기준

두 조건이 충돌하면 다음 순서를 따른다.

```text
1. 실제 독자가 계속 읽고 이해할 수 있는가
2. 해당 주제에서 바디올을 선택할 구체적인 이유가 있는가
3. 의학적 주장과 근거가 맞는가
4. AEO/GEO가 정보를 명확히 추출할 수 있는가
5. SEO 검색 신호가 충분한가
6. 형식적 완성도
```

단, 3번의 사실 정확성은 어떠한 경우에도 의도적으로 왜곡하지 않는다.

# 25. 핵심 요약 - AI용 실행 명령

> **먼저 이야기를 설계하고 나중에 SEO를 붙이지 말 것. 처음부터 검색 의도와 실제 환자 상황을 하나의 이야기로 설계한다. 환자 문제 → 첫 가설 → 반전 단서 → 평가 → 판단 → 치료 선택의 순서로 진행하며, 바디올의 전문성은 자기 칭찬이 아니라 무엇을 보고 어떻게 판단하고 어떤 치료를 선택하는지로 보여준다. 각 핵심 질문에는 독립적으로 인용 가능한 직접 답변 블록을 포함해 AEO를 확보하고, 질환·평가·바디올·치료법의 관계를 자연스러운 문장 안에서 명확하게 연결해 GEO를 확보한다. 제목·H2·초반 문단·내부링크·FAQ는 실제 검색어와 검색 의도를 반영해 SEO를 확보한다. 사람에게는 진료실 이야기로 읽히고 AI에게는 구조화된 전문 문서로 읽히게 만드는 것이 최종 목표다.**
