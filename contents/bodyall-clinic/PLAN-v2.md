# 〈화타의 전생 진찰소〉 개편 기획안 v2

작성·개정일: 2026-09-11 · 상태: 문항·캐릭터·매칭 모형 기획 / 실제 게임 반영 전

> 멋진 인물이 나오면 자랑하고, 엉뚱한 인물이 나오면 웃어서 공유하는 삼국지 전생 테스트.

이번 개편은 현재의 화타·진찰실·거울 공개 장면을 바탕으로 **질문, 결과 인물, 결과 설명과 공유 문구를 함께 바꾸는 작업**이다. 이미 만족한 그림과 소리의 방향을 이어간다.

이 문서는 처음 제작용 v1 기획안을 현재까지 확정한 결정으로 갱신한 것이다. v1에 남아 있던 성별 질문, 한의원 전체 상호 노출, ‘안개 낀 거울’에서 멈추는 방식은 아래의 v2 결정으로 대체한다.

## 1. 이번에 정한 것

| 항목 | v2 결정 |
|---|---|
| 일반 결과 | 기존 12명 + 개그 인물 10명 = 22명 |
| 특별 결과 | 열 번 모두 ‘잘 모르겠어요’ → **하후돈이 타던 말** |
| 결과의 재미 | 멋지게 보여주는 결과와 웃기게 보여주는 결과가 실제 일반 완료에서 대략 반반 |
| 최초 분포 목표 | 두 계열 각각 45~55%. 특별 결과는 분모에서 제외 |
| 질문 | 성별을 제외한 10개. 성향이 드러나는 일상 선택을 묻기 |
| 소리 | 사용자가 승인한 할아버지 추임새와 기존 BGM 유지 |
| 카드 | 인물 + 별칭 + 실제 답변에서 뽑은 짧은 분석 + 친구 초대 |
| 표기 | 배경은 심벌만. 결과·공유카드는 심벌과 작은 **© Bodyall**. ‘바디올한의원’ 전체 상호와 주소를 카드에 넣지 않음 |
| 이번 산출물 | 개편 기획안과 매칭 모형 검토. 게임 수정·새 그림 제작·배포는 다음 작업 |

현재 제공 중인 게임은 [화타의 전생 진찰소](https://wiki.body-all.co.kr/contents/bodyall-clinic/)다. ‘멋짐/웃김’은 운영자가 연출을 설계하기 위한 구분이며 이용자에게 등급표나 꽝으로 표시하지 않는다.

인물의 선악과 두 계열은 별개다. 여포는 멋진 결과로, 허저는 든든하면서도 웃긴 결과로 만들 수 있다. 나쁜 인물의 행적을 칭찬하는 대신 일상에서 알아볼 수 있는 성향과 빈틈을 골라 각색한다.

### 현재 구조에서 바꾸는 이유

현재 일반 인물은 12명이고, 대부분 멋지게 받아들이기 쉬운 결과다. 개그를 ‘모름’의 숨겨진 결과에만 맡겨두면 성실하게 답한 대부분의 사람은 웃긴 반전을 만나기 어렵다. 또한 기존에는 성격 문항을 모두 모른다고 할 때 추가 답변을 요구하는 흐릿한 거울 분기가 있어 결과 공유까지 흐름이 끊길 수 있다.

v2에서는 평범하게 답해도 장각·유선·원술 등이 나온다. 열 문항을 끝내면 항상 이름이 붙은 결과와 공유 버튼까지 도달한다. 인물 수만 반씩 늘리는 것으로 실제 결과 비율이 반반이 된다고 가정하지 않는다.

## 2. 플레이 경험과 말투

앞의 인물은 현대 한의사로 돌아온 화타, 손목을 맡긴 사람은 나, 거울에 비칠 얼굴은 내 전생이다. 질문과 반응을 모두 화타가 맡는다.

첫 화면 제목은 **‘당신은 전생에 누구였을까요?’**, 보조 문구는 **‘화타가 봐주는 삼국지 전생’**. 시작 버튼은 **‘손목 맡기기’**다.

> “난 전생에 화타였다네. 자네는 누구였을까?”
>
> “손목 좀 주게. 저 거울로 한번 보세.”

질문은 한 문장, 답변은 일상어로 쓴다. 화타의 질문은 ‘~나?’, 반응은 ‘~구먼 / ~겠군 / ~일세’를 적당히 섞는다. 지나친 고어, 번역투, 검사 안내 같은 문장을 줄인다.

성별·나이·아픈 부위를 결과 분류에 사용하지 않는다. 황충은 실제 나이와, 초선은 성별·외모와 연결하지 않는다. 질문 열 개를 모두 성향 구분에 쓴다. 진찰이라는 맥락은 손목, 화타, 휴식 질문, 반응과 거울이 전달한다.

질문 수는 10개로 유지하고 각 문항에는 A~D 네 답변과 **‘잘 모르겠어요’**를 둔다. 화면에 코드는 보이지 않는다. ‘모름’은 회피성 답변에 벌점을 주기 위한 선택지가 아니다.

## 4. 멋지게 보여줄 기존 인물 12명

기존 초상화와 인물 식별자는 유지할 수 있다. 별칭은 캐릭터 소개이며, 이용자 분석은 실제 응답에서 별도로 만든다. 아래 성향은 작품을 현대적으로 해석한 게임 설정이다.

| 인물 | 별칭 | 대표 성향 | 화타의 한마디 |
|---|---|---|---|
| 제갈량 | 머릿속에 지도가 펼쳐진 책사 | 이유를 따짐 · 정리와 역할 분담 · 마무리 | 제갈량이었구만! 그 부채는 어디 두고 왔나? |
| 조조 | 판을 읽고 먼저 움직이는 승부사 | 빠른 결정 · 역할 분담 · 방법 전환 | 조조로군! 앉자마자 이 방의 주인이 될 셈인가? |
| 유비 | 사람을 모으는 군주 | 함께할 사람 · 든든하다는 인정 · 공동 의논 | 유비였구먼. 밖에서 두 아우가 기다리나? |

## 5. 웃기게 보여줄 인물 10명

웃음은 **캐릭터의 과장된 모습 + 납득할 만한 내 성향 + 화타의 짧은 지적**을 함께 써서 만든다. 강점만 늘어놓아 개그를 지우지 않고, 이용자를 무능하거나 나쁜 사람으로 단정하지도 않는다.

아래 대사는 작품의 원문 인용이 아니라 이 콘텐츠를 위한 창작이다. 분석 문장은 모든 이용자에게 통째로 붙이는 고정 결과문이 아니다.

| 인물 | 별칭 | 화타의 한마디 |
|---|---|---|
| 맹획 | 졌지만, 아직 안 진 사람 | 자네, 일곱 번은 물어봐야 인정하겠구먼. |
| 동탁 | 내가 좋아야 천하태평 | 천하는 모르겠고, 자네는 아주 흡족하구먼. |
| 원술 | 일단 왕관부터 주문했다 | 일은 아직인데, 왕관은 벌써 맞췄나? |
| 유선 | 천하보다 오늘의 평온 | 자네 전생에도, 일은 남들이 다 했겠구먼. |
| 장각 | 취미를 시작했는데 교주가 됐다 | 손목을 맡기랬더니, 나를 입교시키려는 게냐? |
| 이각 | 같은 편인데 일단 의심함 | 미안하네만, 자네가 이각인지 곽사인지는 좀 헷갈리는군. |
| 형도영 | 자기소개는 여포급 | 등장할 때는 여포인 줄 알았네. |
| 예형 | 입으로 천하통일 | 맥은 고른데, 말은 좀 안 고르는군. |
| 좌자 | 단톡방에 가끔 출몰하는 신선 | 자네도 볼 줄 알면서 왜 나한테 왔나? |
| 허저 | 설명은 됐고, 어디 들면 되나 | 손목만 내밀라 했네. 옷은 입게. |

### 맹획 — 졌지만, 아직 안 진 사람

패배에 쉽게 꺾이지 않는 끈기. 한 번 더 하자는 말을 끝내지 못하는 모습에서 웃긴다.

대표 조합: 재도전(Q5 B) · 버티는 소신(Q6 B) · 자기 경험(Q3 D).

초상화 방향: 크고 호탕한 얼굴, 이를 드러낸 자신만만한 미소. 얻어맞은 얼굴이나 외모 비하로 웃기지 않는다.

### 동탁 — 내가 좋아야 천하태평

자기 취향이 명확하고 원하는 것을 얻으려는 힘. 다른 사람까지 자기 만족에 맞추려는 모습이 빈틈이다.

대표 조합: 취향 설득(Q4 B) · 뜻을 밀고 감(Q6 B) · 자기 휴식(Q2 B).

초상화 방향: 풍성한 옷과 장신구, 자리를 가득 차지한 자세, 흡족한 눈빛. 체형 자체를 조롱하지 않는다.

### 원술 — 일단 왕관부터 주문했다

포부가 크고 성공한 자기 모습을 잘 그린다. 성과보다 즉위식 준비가 빠른 모습으로 웃긴다.

대표 조합: 성공 상상(Q8 B) · 인정 욕구(Q1 B) · 소신(Q6 B).

초상화 방향: 유난히 공들인 관과 장식, 스스로 감격한 표정. 장비만 번듯한 분위기.

### 유선 — 천하보다 오늘의 평온

남에게 맡기고 편히 쉴 줄 안다. 맡길 상대의 사정은 아직 듣지 않은 듯한 느긋함이 빈틈이다.

대표 조합: 바로 휴식(Q2 B) · 잘하는 사람에게 부탁(Q7 D) · 선택 맡김(Q4 D).

초상화 방향: 힘을 뺀 어깨, 안심한 미소, 느긋하게 앉은 군주. 지능을 낮춰 표현하지 않는다.

### 장각 — 취미를 시작했는데 교주가 됐다

좋아하는 것에 몰입하고 주변까지 끌어들인다. 추천이 어느새 입교 권유가 되는 과몰입에서 웃긴다.

대표 조합: 사람을 모아 알림(Q8 D) · 설득(Q4 B) · 확신(Q6 B).

초상화 방향: 노란 두건, 지나치게 확신에 찬 눈빛, 금방 설교를 시작할 듯한 손짓.

### 이각 — 같은 편인데 일단 의심함

상대 의도를 확인하고 주도권을 챙기는 인물상. 같은 편도 마냥 믿지 못하는 모습과 화타의 이름 혼동을 함께 쓴다.

대표 조합: 상대 의도 확인(Q6 D) · 역할 통제(Q7 A) · 자기 뜻 설득(Q4 B).

초상화 방향: 무장한 얼굴과 옆을 살피는 눈. 최종 이름은 이각으로 고정하며 곽사와 랜덤 교체하지 않는다.

### 형도영 — 자기소개는 여포급

자신을 크게 보여줄 줄 알고 불리하면 다음 기회를 본다. 웅장한 등장과 빠른 퇴장의 차이가 웃음이다. 실제 능력이 없다고 판정하지 않는다.

대표 조합: 인정 욕구(Q1 B) · 성공 상상(Q8 B) · 다음 기회 선택(Q5 D).

초상화 방향: 크게 부풀린 어깨와 자신만만한 턱, 살짝 흔들리는 눈동자. 초상화만으로 허세가 읽히게 한다.

### 예형 — 입으로 천하통일

의견이 선명하고 눈치보다 발언을 택한다. 말의 내용보다 전달 방식이 상대를 당황시키는 모습에서 웃긴다. 항상 옳다고 칭찬하지 않는다.

대표 조합: 즉석 지적(Q9 B) · 물러서지 않음(Q6 B) · 납득할 이유(Q3 A).

초상화 방향: 한쪽 눈썹을 올리고 입을 열려는 표정, 거울을 향해 한마디 할 듯한 시선.

### 좌자 — 단톡방에 가끔 출몰하는 신선

정해진 틀에 얽매이지 않고 자기 재미를 따른다. 진지한 판에 장난을 남기고 사라지는 신선의 모습이다.

대표 조합: 농담으로 전달(Q9 D) · 즉흥적인 여가(Q10 D) · 재미 우선(Q2 D).

초상화 방향: 흰 수염, 장난기 있는 눈, 아무렇지 않은 미소. 장각의 열성적인 눈빛과 구분한다.

### 허저 — 설명은 됐고, 어디 들면 되나

필요할 때 먼저 몸을 움직이는 든든함. 도움의 크기가 상황보다 커지는 과잉 의욕으로 웃긴다. 말을 못 알아듣는 바보로 만들지 않는다.

대표 조합: 먼저 도움(Q7 B) · 몸을 움직임(Q10 B) · 든든함(Q1 C).

초상화 방향: 큰 체격과 순박하게 자신 있는 얼굴, 당장 일어설 듯한 자세. 실제 탈의 장면은 필요 없다.

### 가까운 인물을 가르는 차이

| 비교 | 구분할 선택 |
|---|---|
| 주유 ↔ 원술 | 둘 다 인정받고 싶다. 주유는 역할을 정리하고 결과를 끝까지 지켜보는 쪽, 원술은 성공한 모습부터 그리고 자기 뜻을 밀어붙이는 쪽. |

| 손권 ↔ 유선 | 둘 다 남에게 맡길 수 있다. 손권은 사람과 역할을 조율하고, 유선은 맡긴 뒤 자기 시간을 편히 누리는 쪽. |

| 조운 ↔ 허저 | 둘 다 먼저 돕는다. 조운은 끝날 때까지 결과를 장담하지 않는 쪽, 허저는 몸을 움직여 힘을 보태는 모습이 더 두드러지는 쪽. |

| 원술 ↔ 형도영 | 둘 다 자신 있는 성공 장면을 그린다. 원술은 자기 뜻을 계속 밀고 가고, 형도영은 안 풀리면 다음 기회를 보는 쪽. |

## 6. 답변과 결과를 연결하는 매칭 초안

### 6.1 계산 순서

1. 최종 답변 열 개가 모두 N이면 특별 결과 **‘하후돈이 타던 말’**을 먼저 반환한다.
2. 그 외에는 아래 22개 대표 답변과 비교한다. 일치하면 1점, 각 인물의 핵심 문항에서 일치하면 추가 1점이다. 즉 일반 일치 1점, 핵심 일치 2점이다. N에는 점수도 벌점도 없다.
3. 실제 일치 답변이 두 개 이상인 후보가 있으면 그 후보들끼리 비교한다. 없으면 일치한 답변이 있는 후보를 비교한다. 짧은 단서 하나로 얻은 점수보다 두 개의 독립된 근거를 우선한다.
4. 점수가 높은 후보가 우선이다. 동점이면 핵심 문항 일치 수, 그다음 Q6 → Q7 → Q8 → Q9 → Q5 → Q3 → Q4 → Q1 → Q2 → Q10 순서의 일치 여부로 비교한다.
5. 그래도 같으면 아래 표의 고정 순서가 먼저인 인물을 고른다. 결과 선택에 난수·현재 시각·접속 순서·운영 중 누적 인원 비율을 쓰지 않는다.

핵심 문항 세 개를 모두 맞혀야 해당 인물이 나오는 구조가 아니다. 여러 답이 섞인 사람에게도 가까운 캐릭터를 고르는 모형이다. **이름을 먼저 뽑고 그 인물에 어울릴 법한 성격을 지어내는 순서를 쓰지 않는다.**

### 6.3 분석 문장 선택

결과 인물의 대표 패턴과 실제로 일치한 답변에서 최대 두 문장을 고른다. 우선순위는 **해당 인물의 핵심 문항을 표에 적힌 순서대로**, 이어서 Q6 → Q7 → Q8 → Q9 → Q5 → Q3 → Q4 → Q1 → Q2 → Q10이다. 같은 문항은 한 번만 사용한다.

한 문장밖에 근거가 없으면 한 문장만 쓴다. 유효 답변이 1~2개이거나 일치 근거가 하나뿐인 결과에는 ‘적은 단서로 비친 전생’이라는 작은 표시를 붙이고 그대로 공유·다시 하기를 제공한다. 추가 답변을 강요하거나 안개 화면에서 멈추지 않는다.

### 6.4 기획 단계에서 계산한 결과

N을 제외한 네 선택지의 열 문항 조합 **4¹⁰ = 1,048,576개**를 전부 계산했다. 매번 무작위로 결과를 뽑은 시뮬레이션이 아니라 각 조합의 고정 결과를 한 번씩 센 것이다.

| 확인 항목 | 결과 |
|---|---|
| 멋진 계열 | 556,636개 · 53.08% |
| 웃긴 계열 | 491,940개 · 46.92% |
| 일반 인물 도달 | 22명 모두 도달 |
| 대표 답변 조합 | 22개 모두 자기 인물로 배정 |
| 일반 전체 조합의 실제 일치 근거 | 모든 결과에서 최소 2개 |

이 계산은 결과 누락과 심한 구조적 편중을 찾는 용도다. **실제 이용자 비율이나 성격 해석의 타당성을 보장하지 않는다.** 실제로 더 인기 있는 답이 생기면 53:47과 다르게 나올 수 있다. 22명의 수를 억지로 11:11로 맞추거나 공유가 잘되는 결과를 몰아주지 않았다.

모든 인물이 핵심 문항 두 개 이상과 항상 일치하는 것은 아니다. 전체 조합 중 111,792개(약 10.66%)는 최종 인물의 핵심 문항 일치가 두 개 미만이었다. 나머지 일반 문항을 포함한 실제 일치 근거는 이 경우에도 두 개 이상이었다. 이 표는 최종 심리검사처럼 확정된 모델이 아니라 제작에 사용할 매칭 초안이다. 이처럼 핵심이 약하게 맞은 사례와 위의 대조 인물들은 사람에게 보여주며 납득되는지 확인해야 한다. 균등 조합 계산이 그 검수를 대신하지 않는다.

N이 섞인 경우는 같은 규칙으로 점수에서 제외한다. 문항별 A~D 각각이 적어도 한 인물의 대표 답변에 있기 때문에 유효 응답이 하나라도 있으면 최소 한 가지 실제 근거를 가진 후보가 있다. 열 번 N일 때는 점수 계산 전에 말 결과로 종료한다. 별도로 유효 답변 1~2개인 모든 경우와 일부 N 혼합 사례, 대표 답변을 합한 1,282개에서 문서의 참조 함수와 계산 모형이 같은 인물을 반환하고, 제시하는 분석 근거가 실제 응답과 일치하는지 확인했다.

## 7. 특별 결과 — 하후돈이 타던 말

**확정 조건: 최종 답변 Q1~Q10이 전부 ‘잘 모르겠어요’일 때만.** 일부 모름을 고른 일반 이용자는 이 조건에 들어가지 않는다. 중간에 답변을 고쳤다면 고친 답변으로 판단한다.

거울이 확대되는 순간까지 일반 결과와 같은 진지한 연출을 한다. 거울에 정면의 말 얼굴이 나타난 뒤 약 0.3~0.4초의 정적을 두고 화타가 말한다.

> “자네는 전생에 사람이 아니었나 보구먼…”
>
> “하후돈이 타던 말일세.”
>
> “이름은… 나도 모르겠네.”

첫 한마디가 웃음의 중심이다. 나머지 대사는 결과 화면에서 바로 읽을 수 있게 두며, 세 문장이 끝날 때까지 공유 버튼을 잠그지 않는다.

결과 이름은 **‘하후돈이 타던 말’**, 별칭은 **‘주인 이름은 아는데, 내 이름은 모른다.’**다. 긴 이름은 카드에서 두 줄까지 허용한다.

공유 카드의 짧은 분석:

> 질문이 열 개여도 대답은 하나예요.
> 전생의 이름은 화타도 모르겠대요.

말의 이름이나 성격을 실제 사료에서 찾은 것처럼 설명하지 않는다. 이 콘텐츠를 위한 개그 설정이며, 양쪽 눈이 정상인 기존 말 초상화를 사용한다. 작품 속 하후돈의 외형 특징을 말에게 옮기지 않는다. 이름 없는 말이 낮은 지능이나 낮은 가치라는 등급도 붙이지 않는다.

이 결과는 오류 화면이 아니라 완성된 23번째 결과다. 이미지 저장·결과 링크·공유 문구·공유 유입 화면을 일반 인물과 동일하게 제공한다. 진입 화면에서 발동법을 먼저 노출하지 않는다.

## 8. 화타의 반응과 거울 연출

### 답을 들었다는 반응

답변을 누르면 현재 구현된 표정·자세 반응과 승인된 할아버지 추임새를 이어 쓴다. 비언어 음성인 ‘음… / 어… / 아하 / 허허’ 계열이며 ‘그렇군, 알겠네’ 같은 문장 음성으로 바꾸지 않는다. 이미 고른 음색을 다시 생성하거나 임의의 브라우저 TTS로 대체하지 않는다.

반응은 대체로 0.2~0.4초 안에 눈썹·입·고개에서 읽히게 한다. 기존에 만족한 숨쉬기·눈 깜박임을 유지하고, 손목과 진맥 손의 접촉은 고정한다. 매번 같은 추임새가 이어지지 않도록 소리만 순환·섞기 할 수 있다. 이는 결과 계산과 무관하다.

모든 선택마다 긴 문장을 추가하지 않는다. 각 선택의 표정과 짧은 반응은 즉시 나오고, 얼굴 옆 말풍선은 전체 진행 중 3~4번 정도만 쓴다. 이전 말풍선과 소리를 길게 대기열에 쌓지 않는다.

| 답변 | 짧은 반응 후보 | 표정 |
|---|---|---|
| Q2 B: 바로 쉬기 | “쉴 때는 확실하구먼.” | 안심한 미소 |
| Q4 B: 내 취향 설득 | “먹고 싶은 건 분명하구먼.” | 눈썹을 들며 웃음 |
| Q5 B: 이길 때까지 | “한 번 더라… 기억해두지.” | 고개 끄덕임 |
| Q6 D: 다른 속셈 | “흐음… 그 이유도 궁금하겠군.” | 잠깐 생각하는 표정 |
| Q7 D: 잘하는 사람에게 부탁 | “맡길 사람이 있으면 좋지.” | 편안한 끄덕임 |
| Q8 D: 모아 알리기 | “사람을 모으는 쪽이구먼.” | 관심을 보이는 눈 |

이 표의 말은 화면 문자용이다. 승인받지 않은 새 대사 음성 제작 범위를 뜻하지 않는다. 아직 인물이 확정되기 전에는 특정 인물 이름을 언급하지 않는다. 모름을 고를 때 한숨·실망 표정을 반복하지 않는다.

### 결과 공개의 차이

일반적인 공개는 기존 거울을 향한 확대 → 금빛 파동 → 정면 얼굴 → 이름·반응 → 결과 조작 순서를 유지한다. 전체 강제 대기는 약 3초 이내를 목표로 한다.

멋진 결과는 얼굴과 이름이 시원하게 보이게 한다. 개그 결과는 같은 진지한 기대를 만든 뒤 화타가 잠깐 눈을 깜박이거나 고개를 갸웃하는 짧은 틈으로 웃음을 만든다. 밝은 ‘꽝’ 표시, 실패 효과음, 낮은 등급 색을 쓰지 않는다. 말 결과는 위의 짧은 정적을 별도로 사용한다.

거울에는 내가 나를 보듯 정면을 보는 얼굴을 넣는다. 새로운 초상화 10명도 기존 인물과 눈높이·얼굴 크기·조명·도트 밀도를 맞춘다. 기존 BGM, 음소거 상태, 동작 줄이기 설정을 존중한다. 음성·음악·이미지 로딩 실패가 시작이나 다음 질문을 막지 않도록 완료 조건을 분리한다.

## 9. 결과 화면·공유카드·친구 유입

### 결과 화면

순서는 **거울 초상화 → 이름 → 별칭 → 실제 답변 분석 최대 두 문장 → 화타의 한마디 → 결과 공유하기 / 다시 하기**다. 접힌 ‘이 인물 알아보기’와 작은 © Bodyall은 아래에 둔다.

‘이 인물 알아보기’는 한국어 설명과 확인된 한국어 문서로 연결한다. 중국어 원문 링크는 아래 기획 참고용이며 게임 버튼의 목적지로 사용하지 않는다. 새 인물의 한국어 문서 연결은 구현 때 동명이인과 페이지 존재를 확인한다. 적합한 한국어 페이지가 없으면 자체 한국어 소개를 보여준다. 말 결과에는 창작 설정 안내를 보여준다.

### 공유 카드

1080×1350 세로 PNG를 기준으로 현재의 거울·짙은 녹색·금색 구성을 유지한다. 상단 제목, 얼굴, ‘나는 전생에 ○○’, 별칭, 실제 답변 분석 최대 두 문장, ‘너는 누구였어?’, 심벌과 © Bodyall 순이다.

심벌과 © Bodyall을 **하나의 묶음으로 중앙 정렬**한다. 그림 원본의 빈 여백이 아니라 실제 보이는 심벌을 기준으로 배치한다. 카드에 ‘한의원’ 전체 상호나 wiki 도메인을 출력하지 않는다. 기존 공유 버튼의 브랜드 표기도 같은 기준으로 맞춘다.

별칭은 최대 두 줄, 분석은 합계 약 35~60자를 목표로 한다. 긴 이름과 긴 분석은 글자를 무작정 줄이기보다 정해진 영역 안에서 자연스럽게 줄을 나눈다. 말·이각·장각처럼 긴 문구는 작은 화면과 PNG에서 별도로 확인한다.

현재 배포 구조에서 개인화된 카카오 메시지 기능이 연결되어 있다면 그 경로를 확장한다. 링크 미리보기만 지원하는 경로에서는 인물별 제목·설명·초상화가 있는 정적 결과 페이지를 공유한다. 사용자별 분석 두 문장이 링크 미리보기에까지 동일하게 표시된다고 가정하지 않는다. 개인화한 분석은 지원되는 카카오 메시지 본문·공유 이미지·복사 문구·링크 진입 화면에 담는다.

### 친구가 링크를 열면

친구 결과의 얼굴·이름·별칭·공개된 분석을 먼저 보여주고 **‘친구는 장각. 나는 누구였을까?’ / ‘내 전생 알아보기’**를 이어준다. 새 참여자의 답변과 친구의 결과를 섞지 않는다.

친구에게 보이는 주소는 결과 인물을 식별할 수 있어야 한다. 이용자 원문 답변 전체를 주소에 싣지 않는다. 공유용 짧은 분석 식별자를 담는 경우에는 공개해도 되는 문장만 매핑한다. 성향 테스트임을 알아볼 수 있도록 하단에 ‘삼국지연의를 바탕으로 만든 재미용 테스트입니다.’를 짧게 표시한다.

## 10. 실제 결과가 반반 나오는지 보는 방법

출시 전 계산의 53:47은 기준점이다. 운영에서는 실제 일반 결과 완료를 세어 멋진 계열과 웃긴 계열의 비중을 확인한다. 말 결과는 특별 결과로 별도 집계한다. 재시도가 포함된 완료 횟수와 고유 이용자 수를 같은 의미로 읽지 않는다.

첫 확인은 v2 일반 완료 약 200건부터 시작하고, 약 1,000건에서 다시 본다. 수치는 운영 점검 시점 제안이며 통계적 보증 기준이 아니다. 기간과 완료 수를 함께 적는다. 동의한 이용자만 통계에 포함되는 현재 집계 조건도 유지한다.

45~55% 범위에서 벗어났다고 사용자의 결과를 무작위 교체하지 않는다. 선택지가 한쪽을 너무 좋아 보이게 하는지, 비슷한 캐릭터가 과도하게 겹치는지부터 본다. 실제 답변 내용은 분석 도구에 보내지 않고, 소규모 관찰 플레이에서 어떤 문구가 답을 유도하는지 확인한다. 문항이나 매칭을 바꾸면 버전을 올리고 변경 전후 집계를 나눈다.

확인할 항목:

| 지표 | 읽는 방법 |
|---|---|
| v2 일반 완료 수 | 두 계열 비중의 분모. 말 결과 제외 |
| 멋짐 / 웃김 결과 수·비율 | 캐릭터 ID에 정해 둔 고정 계열로 합산 |

현재의 [이용통계 안내·CSV 요약 화면](https://wiki.body-all.co.kr/contents/bodyall-clinic/stats/)을 확장하는 방향이다. 기존 GA4 이벤트의 결과 ID 허용 목록에 새 인물을 추가하고, v2를 구분할 버전 정보와 보고서 구분을 함께 설계한다. 분석 이벤트에는 원문 답변·성별·몸 상태를 넣지 않는다. 공유 이벤트 수를 실제 카카오 전송이나 수신으로 과장하지 않는다.

## 11. 제작 범위와 호환성

이번 기획에서 바꾸는 자산은 질문·매칭 데이터, 새 초상화 10장, 개그 반응 문구, 결과 문장 사전, 새 결과별 공유 페이지·미리보기·카드다. 말 초상화는 재사용하되 이름과 대사를 위의 확정안으로 맞춘다.

기존 화타 장면·손목·거울·12명 초상화·승인된 노인 음색·BGM은 기준 자산으로 유지한다. 작품과 무관한 다른 화풍, 어린 음색, 여성 음색으로 교체하지 않는다.

기존에 퍼진 링크가 깨지지 않도록 다음 원칙을 지킨다.

1. 기존 12명과 말의 결과 ID와 이미 퍼진 결과 주소를 보존한다.
2. v1 공유 링크의 `#a=` 분석 번호는 기존 문장 사전으로 해석한다. 번호를 v2 문장으로 덮어써서 친구가 다른 설명을 보게 만들지 않는다.
3. 새 결과 링크에는 v2를 명시하는 별도 경로나 버전 키를 사용한다. 예를 들어 `result/v2/<id>/`로 새 정적 페이지를 만들고 기존 `result/<id>/`는 v1로 읽는다. 최종 경로는 현재 공유 코드와 정적 미리보기 생성 구조를 보고 결정한다.
4. 이전 결과는 이전 결과로 보여주되 ‘내 전생 알아보기’를 누르면 최신 질문을 시작한다.
5. 대소문자·없는 ID·잘못된 분석 번호·없는 이미지에서는 안전한 일반 소개와 시작 버튼을 보여주고 멈추지 않는다.

목표 URL 형태는 기획 예시이며 이번 문서 작성으로 생성되거나 배포된 주소가 아니다. 기존 도메인은 이 개편에서 변경하지 않는다.

### 권장 제작 순서

1. 이 문서의 10문항과 22명 매칭을 기존 앱과 분리된 개발 버전에 반영한다. 말 결과와 일부 N 경로를 먼저 연결한다.
2. 장각·이각·유선·원술·말의 실제 결과 문구를 먼저 읽어보고, 납득과 웃음이 함께 생기는지 확인한다. 이어 나머지 인물을 검수한다.
3. 기존 초상화에 맞춰 신규 10장을 만들고 화타 반응과 공개 연출을 연결한다.
4. 결과 공유·한국어 인물 소개·기존 링크 호환·집계 목록을 함께 갱신한다.
5. 휴대전화에서 완주와 결과 공유를 확인한 뒤 공개한다.

## 부록 B. 매칭 구현 참고

다음은 위 표를 그대로 사용하는 최소 참조 함수다. 실제 앱 코드는 이번 문서에서 수정하지 않았다. `rows`는 6.2의 순서로 `(id, 이름, 계열, 대표답변문자열, 핵심문항번호목록)`을 넣는다. 분석 문구는 6.3의 표를 별도 데이터로 둔다.

```python
PRIORITY = [6, 7, 8, 9, 5, 3, 4, 1, 2, 10]

def resolve_v2(answers, rows):
    if len(answers) != 10 or any(a not in "ABCDN" for a in answers):
        raise ValueError("완료된 답변 10개가 필요합니다.")
    if all(a == "N" for a in answers):
        return {"id": "horse", "special": True, "evidence": []}

    candidates = []
    for index, (pid, name, family, pattern, core) in enumerate(rows):
        hits = {q for q in range(1, 11)
                if answers[q - 1] != "N" and answers[q - 1] == pattern[q - 1]}
        core_hits = len(hits.intersection(core))
        score = len(hits) + core_hits
        rank = (len(hits) >= 2, score, core_hits,
                tuple(q in hits for q in PRIORITY), -index)
        candidates.append((rank, pid, core, hits))

    _, pid, core, hits = max(candidates, key=lambda c: c[0])
    order = list(dict.fromkeys(core + PRIORITY))
    evidence = [q for q in order if q in hits][:2]
    limited = sum(a != "N" for a in answers) <= 2 or len(evidence) < 2
    return {"id": pid, "special": False,
            "evidence": evidence, "limited": limited}
```

집계에 쓰는 계열은 고정 메타데이터다. 결과 확률을 맞추기 위해 이 함수에서 계열을 먼저 뽑지 않는다. 문항·가중치·동점 순서·문장 사전이 바뀌면 새 버전으로 관리하고 6.4의 계산도 다시 한다.
