# 화타 이용통계 — 연결과 조회

## 현재 상태

계측 코드·한글 CSV 조회 화면·검증을 준비했습니다. Google Analytics 관리 화면은 로그인이 필요하며, 웹 스트림의 측정 ID를 확인하기 전에는 `analytics-config.js`를 `enabled:false`로 유지합니다. **이 상태에서는 실제 집계가 시작되지 않습니다.** 코드 검사와 Google 수신 검증은 다른 단계입니다.

기반 main: `aa874863754453228e0ba4717e5861b622c99b27`.
기존 연결 앱에서 읽을 수 있는 GA4 속성은 `517564179` 하나지만, 해당 속성의 실제 웹 스트림·용도·측정 ID는 아직 확인하지 못했습니다. 속성 숫자를 `G-` 측정 ID처럼 사용하거나 무관한 사이트의 스트림을 재사용하지 않습니다.

## 마지막 연결 절차

1. Google Analytics 관리 화면에서 로그인하고 게임에 사용할 계정과 웹 데이터 스트림을 확인합니다. 적합한 기존 스트림이 없으면 게임용 스트림 또는 속성을 구성합니다. 별도 유료 서비스는 신청하지 않습니다.
2. 측정 ID `G-...`, 실제 GA4 속성 ID, 보고서·실시간 화면의 URL을 확인해 `analytics-config.js`에 기록합니다. 비밀번호·OAuth 토큰·Measurement Protocol 비밀키는 사이트에 넣지 않습니다.
3. 향상된 측정은 이 게임 스트림에서 끕니다. 자동 검색어·스크롤·외부 링크·동영상·폼 측정을 사용하지 않고, 이 코드의 허용된 게임 이벤트만 계측합니다. 다른 위키 페이지에 쓰이는 공용 스트림의 설정을 임의로 바꾸지 않습니다.
4. 광고 개인화와 Google Signals를 사용하지 않습니다. 이벤트 데이터 보관은 2개월, 새로운 활동에 따른 보관기간 재설정은 끔으로 구성합니다. 이 설정은 집계 보고서와 원시 이벤트의 보관 범위를 동일하게 만들지는 않습니다.
5. `enabled:true`로 바꾸고 기존 GitHub Pages 경로에 배포합니다. 현재 main을 재확인하고 게임 폴더 밖의 작업은 보존합니다.
6. 공개 사이트에서 ‘통계 참여’를 누른 뒤 시작→10문항→결과→공유 시도를 실행합니다. GA4 실시간/DebugView에서 해당 이벤트 수신을 확인합니다. 테스트 트래픽은 운영 수치와 구분해 기록합니다. 카카오톡 실제 발송·읽음을 검증한 것으로 표현하지 않습니다.
7. 확정 이벤트 보고서에 데이터가 표시되면 게임 이벤트로 필터링하고 CSV를 내보내 한글 조회 화면과 수치를 대조합니다. 원장님에게 실제 확인한 보고서 URL과 조회 경로를 제공합니다.

## 원장님 조회 방법

- 수집 직후: `stats/`의 ‘실시간 수신 확인’ → 현재 들어오는 이벤트 확인.
- 일별/주별: ‘이벤트 보고서 열기’ → 최근 7일 또는 30일 → 이벤트 이름 `huata_`로 필터링.
- 한글 요약: 전체 게임 이벤트 CSV 내보내기 → `stats/`에서 파일 선택. 시작·완료·공유·공유 초대 참여·질문별 도달·인물별 공유를 한글로 정리합니다. CSV 방식은 새 파일을 읽기 전까지 자동 갱신되지 않습니다.
- `dashboardURL`은 실제 만든 자동 대시보드가 있을 때만 설정합니다. 빈 설정을 연결 완료나 자동 갱신으로 표현하지 않습니다.
- 별도 Data Studio 자동 대시보드가 필요하면 GA4 데이터 소스를 연결하고 아래 지표를 구성합니다. 현재 HTML은 비공개 통계를 공개 서버에 올리거나 인증 없이 직접 읽는 관리자 페이지가 아닙니다.

## 측정 항목

모든 이벤트는 `huata_` 접두사를 써서 기존 사이트 데이터와 구분합니다. `content_group=huata`를 함께 보냅니다. 기본 속성은 게임 버전, 페이지 종류, 정리한 페이지 URL·참조 도메인이며, 이벤트별 허용한 인물 ID만 선택적으로 포함합니다. 원문 답변·건강 정보·성별·개인식별정보·분석 문장은 보내지 않습니다.

| 이벤트 | 화면의 의미 | 집계 단위 |
|---|---|---|
| huata_visit | 게임 페이지 방문 | 측정에 참여한 페이지 로드 |
| huata_start | 플레이 시작 | 손목 맡기기/다시하기로 시작한 플레이 |
| huata_step_01 ~ 10 | 질문별 도달 | 한 플레이에서 질문당 1회, 보충 질문 제외 |
| huata_complete | 결과 확인 | 한 플레이에서 실제 인물/말 결과를 처음 본 1회 |
| huata_fog | 안개 결과 | 한 플레이당 1회, 완료와 구분 |
| huata_result_ID | 인물별 결과 | 완료된 플레이의 인물 |
| huata_share_open | 공유 화면 열기 | 완료된 플레이당 1회 |
| huata_share_attempt | 공유 버튼 시도 | 완료된 플레이당 1회 |
| huata_share_returned | 공유 API가 성공으로 반환 | 완료된 플레이당 1회, 발송 완료가 아님 |
| huata_copy | 링크 복사 성공 | 완료된 플레이당 1회 |
| huata_save | 이미지 저장 버튼 실행 | 완료된 플레이당 1회, 저장 완료가 아님 |
| huata_share_intent | 공유 의도 | 공유 시도 또는 복사가 발생한 플레이당 1회 |
| huata_result_share_ID | 인물별 공유 의도 | 공유 의도가 발생한 플레이의 인물 |
| huata_shared_view | 공유 결과 페이지 방문 | 측정에 참여한 페이지 로드 |
| huata_shared_start_click | 공유 결과에서 테스트 버튼 클릭 | 공유 결과 페이지당 1회 |
| huata_friend_start | 공유 초대에서 플레이 시작 | 유효한 인물 ID와 from=friend가 있는 시작 |
| huata_creator_click | 제작자 링크 클릭 | 게임 페이지당 1회 |

`ID`는 zhuge, cao, liu, guan, zhang, zhao, sun, zhou, sima, huang, lu, diao, horse 중 하나입니다. 고정된 이벤트 이름 덕분에 별도 맞춤 측정기준을 등록하지 않아도 기본 이벤트 보고서 CSV에서 인물별 수치를 볼 수 있습니다.

## 지표 해석

- 완료 / 시작 비율 = huata_complete ÷ huata_start.
- 공유 의도 / 완료 비율 = huata_share_intent ÷ huata_complete.
- 인물별 공유 비율 = huata_result_share_ID ÷ huata_result_ID.
- 위 비율은 조회 기간 내 이벤트 수의 비율입니다. 엄밀한 사용자 코호트 전환율이 아니며, 시작과 완료의 날짜가 갈리면 기간 경계 오차가 있습니다.
- 같은 사람이 다시 하면 새로운 플레이입니다. 고유한 실제 사람 수로 표현하지 않습니다.
- 공유 초대 유입에는 본인이 링크를 다시 연 경우도 포함될 수 있습니다. 최초 공유자별 추천 관계나 정확한 카카오톡 전송 경로는 추적하지 않습니다.
- 참여 선택 전은 최대 160개의 허용된 진행 이벤트만 현재 페이지 메모리에 임시 보관합니다. 참여하면 전송하고, 거절하거나 페이지를 닫으면 버립니다. 지속적인 추적 식별자는 직접 생성하지 않습니다.
- 추적 차단·통신 실패·미동의 이용은 빠집니다. 보이는 숫자를 전체 이용자 수로 일반화하지 않습니다.
- 질문 간 도달 차이는 이탈을 살펴보는 참고치입니다. 브라우저 종료를 완벽하게 검출한 실제 종료 건수가 아닙니다.
- 게임 결과 비율은 게임의 매칭 규칙과 참여자 구성에 따른 값으로, 일반 인구의 성격/건강 통계가 아닙니다.

## 배포 경로

`?src=kakao|instagram|naver_cafe|naver_blog|community|youtube|offline|bodyall` 중 하나만 허용합니다. 구분 링크는 `stats/`에서 만들 수 있습니다. 링크가 재전달되면 원래 표시가 남을 수 있으므로 실제 사용 앱을 보증하지 않습니다. 임의 URL 매개변수·답변 fragment·참조 페이지 경로는 이벤트에 싣지 않습니다.

## 검증

`node test-analytics.cjs`, `node test-startup.cjs`, `node test-sharing.cjs`.

통계 스크립트는 시작 로딩·화타 모션·음원·결과 공유의 성공 조건이 아닙니다. 광고 차단이나 Google 장애가 게임 진행을 막아서는 안 됩니다. 새 단계의 외부 실제 수신 검증이 끝나기 전에는 완료 상태를 갱신하지 않습니다.
