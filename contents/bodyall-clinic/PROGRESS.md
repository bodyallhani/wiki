## 확장·미확인 범위

현재 대사는 규칙 기반이며 실제 음성 녹음은 없다. 전체 게임이 실행 중 얼굴을 다시 생성하지 않는다. 공유 이미지에는 개인화된 분석이 들어가지만 링크 미리보기까지 개인별로 생성하는 서버는 없다. 수집형 분석 도구와 내원 전환 측정은 연결하지 않았다. 실제 재미와 브랜드 기억은 공개 후 사용자 반응으로 평가한다.

기획서와 완성 자산을 기준으로 이어갈 수 있으며, 이미지 생성 프롬프트는 ARTWORK.json에 기록돼 있다. 불필요하게 전체 이미지를 다시 생성하지 않는다.


## 2026-09-11 — 대화 반응 개선

사용자 요청: 현재 분위기와 게임에는 만족. 답을 고를 때 화타의 표정·자세·리액션이 바뀌고, 호흡과 눈 깜빡임이 보여야 실제 대화처럼 느껴짐.

- `reactions.js`: 50개 선택지 모두 짧은 응답 연결. 성별은 중립적 응답, 몸 상태는 차분히 경청, 성격 답변은 익살스러운 반응. 연속 “잘 모르겠어요”에 따라 말투도 바뀜.
- `actor.js`: 기본·미소·생각·놀람 4개 표정과 각 표정의 눈 감은 그림. 응답 도중 짧게 깜빡이며, 대기 중에도 불규칙하게 깜빡임. 화면 밖·다른 탭·대화창·결과 공개 중 타이머 정지. 움직임 줄이기 환경에서는 표정만 변경.
- `style.css`: 고개 끄덕임·갸웃·살짝 가까이 기울임·놀라 물러남·웃음 동작, 더 눈에 띄는 호흡. 손목 접촉과 거울은 고정된 아래 레이어에 유지.
- 선택 후 0.95초(마지막 질문 1.25초) 동안 반응을 보여준 뒤 진행. 선택 중 중복 입력 방지 유지. 질문·결과 매칭·공유카드 분석은 그대로.
- 새 그림 `assets/huata-expressions.webp`, 원본 프롬프트·좌표·프레임 순서 `REACTION_ARTWORK.json`.

## 2026-09-11 — 시작 로딩 중단 수정

- 사용자 보고: 첫 화면이 “거울을 닦는 중…”에서 진행되지 않음.
- 원인: `actor.js`의 기본 시계가 `{setTimeout, clearTimeout}` 메서드로 브라우저 함수를 호출해 Window 수신자 조건을 위반할 수 있었음. 초기 로딩 완료의 `syncActor()`에서 예외가 나고, 오류 처리에서도 같은 호출이 반복되어 버튼 해제에 도달하지 못함. 기존 테스트의 주입 시계에서는 이 조건을 재현하지 못했음.
- 수정: 기본 시계는 전역 타이머를 호출하는 함수로 감쌈. 표정 제어 오류를 게임 진행에서 분리하고 기본 시작 상태를 먼저 갱신. 표정 스크립트가 없거나 예외를 내도 시작·다음 질문 진행 가능. 파일 캐시 버전 갱신.
- 새 `test-startup.cjs`: HTML의 실제 스크립트 순서와 실제 기본 타이머 경로 실행. Window 수신자 제약을 적용하여 시작 버튼 활성화→첫 질문→첫 답변→두 번째 질문 확인. 표정 초기화/실행 실패와 스크립트 누락 시에도 진행 확인. 실제 브라우저 UI 테스트는 아님.
- `node test-startup.cjs`, `node test-reactions.cjs`, 구문 검사 통과.
