# 바디올 클리닉 — 이 환자, 나잖아?

EP.01 퇴근했지만 종료되지 않은 최대리. 고전 PC게임의 초상화·대화창 감성을 담은 생활공감 선택형 웹게임입니다.

공개 경로: https://wiki.body-all.co.kr/contents/bodyall-clinic/

## 플레이

1. `오늘의 환자 만나기`를 누릅니다.
2. 최대리가 보여주는 물건 다섯 개 중 하나를 고릅니다.
3. 질문 세 개 중 하나를 고릅니다.
4. 실제 획득한 단서 두 개 중 하나의 이야기를 더 들어봅니다.
5. 사연·엔딩을 보고 결과 카드를 공유하거나 다른 경로를 플레이합니다.

30개의 선택 조합, 세 종류의 엔딩, 마지막 단서에 따른 여덟 별명과 공유 카드 문구가 있습니다. 30개가 모두 별개의 장편 이야기는 아닙니다. 제한 시간·건강 점수·실력 평가가 없습니다.

마우스·터치·Tab/Enter로 조작합니다. 대화 중 Space로 다음 대사를 볼 수 있습니다. 효과음은 기본적으로 꺼져 있으며 직접 켜면 짧게 재생됩니다. 기기 음량·브라우저 설정에 따라 들리지 않을 수 있습니다.

## 구현과 복구 범위

2026-09-11 기본 브랜치 `main`의 `2789b29df5a59ae2aff8a71a2c135bd827866879` 및 별도 감사 브랜치의 전체 파일을 확인했습니다. 이전 회피 게임 `contents/spine-off-duty/`만 커밋에 남아 있었고 이 에피소드 소스는 없었습니다. 연결되지 않은 blob은 식별 SHA가 없어 복구 여부를 확인하지 못했습니다.

저장된 `바디올_클리닉_EP01_전체대본_v1.md`(2026-09-10)의 관찰·질문·후속 대화·공통 설명·엔딩 문구를 파싱해 `story.js`로 복구했고 UI·상태 전환·원화·공유 기능은 새로 구현했습니다. 원래 중단된 실행을 재개한 것은 아닙니다.

기존 게임, 의료정보 문서, sitemap, 워크플로는 수정하지 않습니다. 게임 파일은 이 폴더 안에서만 작동하며 프레임워크·패키지 설치·빌드·API 키가 필요 없습니다. 기존 GitHub Pages가 저장소 루트를 게시하면 이 경로가 함께 게시됩니다.

- `index.html`, `style.css`: 반응형 게임 화면, 접근성, 대화·공유·안내 UI.
- `story.js`: 복구한 대본의 고정 대사와 분기 데이터.
- `engine.js`: 선택 순서와 획득 단서 제한을 적용하는 게임 진행.
- `app.js`: 화면, 키보드, 효과음, 이미지 생성, 공유.
- `assets/clinic-room.webp`: 가상 진료실 원화. 실제 내부 사진이 아닙니다.
- `assets/portraits.webp`: 동일한 가상 최대리의 여섯 표정, 3×2 배열.
- `ARTWORK.md`: 원화 제작 프롬프트.
- `test-game.cjs`: 30개 경로·잘못된 선택·재플레이·구문·자산 검사.

## 공유와 데이터

엔딩에서 `이 환자, 친구도 만나보기`를 누르면 공유할 카드와 문구를 먼저 확인합니다. 카드는 브라우저에서 생성하는 1080×1350 PNG입니다. 기본 공유창에서 지원하면 이미지를 함께 보내고, 미지원 환경에는 이미지 저장·문구 복사를 제공합니다. 공유를 취소해도 결과 화면은 유지됩니다. 모바일 운영체제·앱·브라우저별 공유와 다운로드 동작은 다를 수 있습니다. 이미지 저장이 바로 되지 않으면 미리보기 이미지를 길게 눌러 저장할 수 있습니다.

공유 링크에는 `?from=friend`만 붙습니다. 결과나 건강정보를 전달하지 않으며 친구는 시작 화면부터 플레이합니다. 대본에 기재된 여덟 결과 문구를 사용합니다. 카드 소품별 별도 삽화 여덟 장 대신 여섯 표정의 동일 캐릭터와 고정 진료실 배경을 조합합니다.

로그인·이름·증상·연락처를 입력받지 않습니다. 서버 API·분석 SDK·추적 픽셀을 추가하지 않았습니다. 기록과 설정은 현재 페이지 메모리에만 있어 새로고침하면 초기화됩니다. 호스팅 서비스와 외부 이동 대상의 기본 접속 로그까지 없다는 뜻은 아닙니다.

브라우저 내부 `bodyall:game-event` 이벤트만 제공하고 네트워크로 전송하지 않습니다. `game_start`, `game_complete`, `share_preview_open`, `share_api_resolved`, `result_card_export`, `clinic_link_click` 이벤트가 있습니다. 공유 API의 정상 반환은 상대방 수신 확인이 아니며, 다운로드 요청은 기기에 저장 완료되었다는 확인이 아닙니다. 진료 안내 클릭도 예약 완료가 아닙니다.

## 진료 안내

대본의 공통 설명을 모든 엔딩에 똑같이 적용하며 생활 단서로 질병·통증 원인이나 치료 필요성을 정하지 않습니다. 실제 의료진 검수 완료 표시를 넣지 않았습니다.

엔딩에서 별도로 열리는 진료 정보 패널은 기존 공식 [SART 안내](https://wiki.body-all.co.kr/SART.html)로 연결합니다. 2026-09-11 실제 페이지의 위치·진료 안내·상담 연결을 확인했으며, 그 페이지의 모든 효과 주장을 검증했다는 뜻은 아닙니다.

## 확인 방법

`node test-game.cjs`로 30개 선택 경로의 종료, 3종 엔딩, 8종 별명·공유 문구, 미획득 단서 선택 차단, 재플레이 초기화, 로컬 자산 및 JavaScript 구문을 검사합니다.

실제 휴대폰의 터치·공유창·이미지 다운로드와 브라우저 시각 검사는 수행하지 않았습니다. 플레이 시간·재미·바이럴 성과는 실제 사용자 측정값이 없습니다.

WebMCP 지원 브라우저에서는 `read_clinic_story`와 `advance_clinic_story`를 선택적으로 등록합니다. 화면과 같은 선택 제한을 적용하며 공유·외부 이동은 수행하지 않습니다. 이번 환경에는 허용된 지원 브라우저 검증 경로가 없어 실제 등록·호출 검증은 수행하지 않았습니다. 미지원 브라우저에는 영향이 없습니다.
