# 바디올 클리닉 — 이 환자, 나잖아?

EP.01 퇴근했는데 아직도 일하는 최대리 · 대화 명료화 v2

공개 경로: https://wiki.body-all.co.kr/contents/bodyall-clinic/

## 플레이

플레이어는 원장님이고, 화면 속 인물은 직장인 최대리입니다. 역할을 상단에 계속 표시합니다.

1. `원장님으로 시작하기`를 누릅니다.
2. 내가 먼저 건넬 말을 고르면 최대리가 바로 대답합니다.
3. 이어서 물어볼 말을 고릅니다.
4. 마지막 한마디를 고르면 대답과 엔딩이 함께 나옵니다.

버튼 문구는 실제로 내가 하는 말입니다. 선택한 말은 `나 · 원장님`, 답변은 `최대리`로 구분해 같은 화면에 함께 남깁니다. 앞선 물건 이야기를 다시 꺼내는 선택지는 `아까…`로 시작해 화제가 바뀌는 이유를 표시합니다. 별도 대사 넘기기·사연 발견·의학 설명 화면을 없앴습니다.

한 판은 세 번의 말 선택으로 끝납니다. 30개의 선택 조합, 엔딩 세 종류, 마지막 대화에 따른 여덟 별명과 공유 카드가 있습니다. 정답·시간 제한·건강 점수가 없습니다. 엔딩 이름은 게임 속 대화에 대한 별명입니다.

대사를 생활 언어로 고치고 각 답변을 짧은 1~2문장으로 제한했습니다. 30개 경로의 평균 대사 길이는 166자입니다(시작 한마디+선택한 내 말+상대 답변, 버튼 목록·고정 UI 문구는 제외). 실제 플레이 시간이나 재미를 측정한 결과는 아닙니다.

마우스·터치·Tab/Enter로 조작합니다. 효과음은 기본적으로 꺼져 있습니다. 같은 그림·공유 기능을 유지합니다.

## 구현과 복구 범위

2026-09-11 기본 브랜치 `main`의 `2789b29df5a59ae2aff8a71a2c135bd827866879` 및 별도 감사 브랜치의 전체 파일을 확인했습니다. 이전 회피 게임 `contents/spine-off-duty/`만 커밋에 남아 있었고 이 에피소드 소스는 없었습니다. 연결되지 않은 blob은 식별 SHA가 없어 복구 여부를 확인하지 못했습니다.

첫 구현은 저장된 `바디올_클리닉_EP01_전체대본_v1.md`(2026-09-10)를 토대로 복구했습니다. 이후 사용자의 “역할과 문맥이 불분명하고 텍스트가 길다”는 피드백에 따라 대사와 진행 방식을 v2로 개정했습니다. 현재 `story.js`의 문구가 실제 게임과 일치하며, 원본 대본을 그대로 재생하지 않습니다.

기존 게임, 의료정보 문서, sitemap, 워크플로는 수정하지 않습니다. 게임 파일은 이 폴더 안에서만 작동하며 프레임워크·패키지 설치·빌드·API 키가 필요 없습니다. 기존 GitHub Pages가 저장소 루트를 게시하면 이 경로가 함께 게시됩니다.

- `index.html`, `style.css`: 반응형 게임 화면, 접근성, 대화·공유·안내 UI.
- `story.js`: 복구한 대본의 짧게 개정한 대사와 분기 데이터.
- `engine.js`: 선택 순서와 획득 단서 제한을 적용하는 게임 진행.
- `app.js`: 화면, 키보드, 효과음, 이미지 생성, 공유.
- `assets/clinic-room.webp`: 가상 진료실 원화. 실제 내부 사진이 아닙니다.
- `assets/portraits.webp`: 동일한 가상 최대리의 여섯 표정, 3×2 배열.
- `ARTWORK.md`: 원화 제작 프롬프트.
- `test-game.cjs`: 30개 경로·잘못된 선택·재플레이·구문·자산 검사.

## 공유와 데이터

엔딩에서 `친구에게 보여주기`를 누르면 공유할 카드와 문구를 먼저 확인합니다. 카드는 브라우저에서 생성하는 1080×1350 PNG입니다. 기본 공유창에서 지원하면 이미지를 함께 보내고, 미지원 환경에는 이미지 저장·문구 복사를 제공합니다. 공유를 취소해도 결과 화면은 유지됩니다. 모바일 운영체제·앱·브라우저별 공유와 다운로드 동작은 다를 수 있습니다. 이미지 저장이 바로 되지 않으면 미리보기 이미지를 길게 눌러 저장할 수 있습니다.

공유 링크에는 `?from=friend`만 붙습니다. 결과나 건강정보를 전달하지 않으며 친구는 시작 화면부터 플레이합니다. 개정한 여덟 결과 문구와 별명을 사용합니다. 카드 소품별 별도 삽화 여덟 장 대신 여섯 표정의 동일 캐릭터와 고정 진료실 배경을 조합합니다.

로그인·이름·증상·연락처를 입력받지 않습니다. 서버 API·분석 SDK·추적 픽셀을 추가하지 않았습니다. 기록과 설정은 현재 페이지 메모리에만 있어 새로고침하면 초기화됩니다. 호스팅 서비스와 외부 이동 대상의 기본 접속 로그까지 없다는 뜻은 아닙니다.

브라우저 내부 `bodyall:game-event` 이벤트만 제공하고 네트워크로 전송하지 않습니다. `game_start`, `game_complete`, `share_preview_open`, `share_api_resolved`, `result_card_export`, `clinic_link_click` 이벤트가 있습니다. 공유 API의 정상 반환은 상대방 수신 확인이 아니며, 다운로드 요청은 기기에 저장 완료되었다는 확인이 아닙니다. 진료 안내 클릭도 예약 완료가 아닙니다.

## 진료 안내

본편에는 의학적인 문진·진단·치료 설명이 없습니다. 생활공감 대화를 마친 뒤 `바디올 진료 안내`를 직접 눌렀을 때만 기존 진료 정보 패널이 열립니다. 실제 의료진 검수 완료 표시를 넣지 않았습니다.

패널은 기존 공식 [SART 안내](https://wiki.body-all.co.kr/SART.html)로 연결합니다. 2026-09-11 최초 제작 시 확인한 진료·상담 경로를 유지합니다.

## 검증

`node test-game.cjs`로 30개 선택 경로, 정확히 세 번의 선택 후 엔딩 도달, 화면에 표시할 내 말과 실제 선택지의 일치, 앞서 들은 내용에만 이어 묻기, 재플레이 초기화, JavaScript 구문·자산 연결을 검사합니다.

실제 휴대폰의 터치·공유창·저장과 브라우저 시각 검사는 수행하지 않았습니다. 재미·몰입도·전환율은 실제 사용자 검증이 필요합니다.

WebMCP 지원 브라우저에서는 `read_clinic_story`, `advance_clinic_story`를 선택적으로 등록합니다. v2에서는 시작·말 선택·재플레이만 제공하고 현재 대화의 양쪽 화자를 함께 반환합니다. 지원 브라우저에서의 실제 등록·호출 검증은 수행하지 않았습니다.
